# LICHOMAT v0.4: atmosphere — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build v0.4 of LICHOMAT as accepted in §5 of `docs/superpowers/specs/2026-10-29-stage2-draft.md` (written there as "v0.3: atmosfera"; it ships as v0.4 after the reordering of tracker Q24). v0.4 adds a reverb that runs with the delay (delay → reverb), based on fw 1.7's disabled "Plt" reverb with its loop bug fixed, in its own RAM buffer; reverb size, decay, tone, predelay and modulation, at full rate or at half rate by a CPU rule; freeze; rumble (the reverb ducked by a chosen voice); a tempo-synced delay (1/16 to 1/4, dotted and triplet); a DJ filter on both stereo outputs; the version bump, the owner's checks, release notes, kit recipes for washes, and demo renders.

**Architecture:** The reverb is a stage of the FX bus after the slot effect (distortion, ring, compressor or delay). When the reverb's level is 0, `FxBus_process()` keeps v0.3's path bit for bit. Otherwise the slot writes into a scratch bus, the reverb adds its stereo wet signal, and the sum goes to the FX bus output. The reverb's 14 delay units live in a new 57,344 B buffer in RAM. The delay keeps the 64 KB `FX_BUFFER` in DTCM. Five kit parameters reuse sound parameter numbers that fw 1.7 does not use, so NRPN, the LFOs, p-locks and morph reach them. Seven more kit parameters get numbers after the globals and are saved in an extension block after the 247 parameter bytes of the kit file, which fw 1.7 does not read. The DJ filter is a TPT state-variable filter on the four output channels after the FX bus. Rumble ducks the reverb's wet signal with a peak follower on one voice's block.

**Tech Stack:** C11 (firmware: Arm GNU 14.3, `-O3 -ffast-math -mfp16-format=ieee`; host tests: Apple clang 17, UBSan), CMake 3.31, Ninja, ctest, Python 3 (`render_test.py`, `emu_golden.py`, `emu_fuzz.py`), bash.

  - I_loop: instructions in the loop.
  - For each `bl` target f in the loop, n_f: how often it is called per iteration.
  - I_f: all instructions of f, from its label to its last return (`bx lr` or `pop {…, pc}`). This is the longest path for straight-line code.
  - N_div: `vdiv`/`vsqrt` in the loop and in the callees, weighted by n_f.
  - N_buf: buffer loads and stores (`ldrh`/`strh`/`vldr.16`/`vstr.16` and the `vcvtb` pairs next to them) in the loop and in the callees, weighted by n_f.
  - I_out: the instructions outside the loop.

  - The v0.4 additions (D36 R taps, D40 duck gain, level ramp) count as Δ = 5·(I_ReadTapSample + 4) + (I_TiltEq_process + 4) + 10 per sample.

static inline void djf_coef(DjSvfCoef *c, uint8_t pos, uint8_t reso, float fs)

	if(pos < 63) { c->mode = DJF_LP; fc = 20000.f * exp2f(-10.f * (float)(63 - pos) / 63.f); }

## Risks

- **The CPU estimate can be wrong in either direction.** D41's factor 1.5 and U20's fallback (full → half → lean before the release) bound it. Level 0 always frees the reverb's CPU.
- **Stale slot bytes.** Old kits may carry MIDI note numbers in 224–227. The guard (D35) relies on the block's absence. A kit that v0.4 saved and fw 1.7 re-saved still has v0.4 values in the slots, and the guard resets them, so the user loses those settings, as with `.pat`.
- **Two enums.** `Parameters.h` and `ParameterArray.h` must change together (AF6). `drift.py` catches a menu-side mismatch; the A3 grep catches the rest.
- **The FX bus scratch buffer** adds 256 B of stack in the audio interrupt (DTCM stack ≥ 23 KB, D30). A1 records `Reverb_process`'s own stack.
- **The reverb in RAM** runs through the D-cache (AF12). The 24 or so streams cost about one miss per 16 samples each, which A1 counts as 2 cycles per access.
- **v0.3 F17 was wrong** (AF5). Nothing in v0.3 depends on it. The release notes correct it.
