# LICHOMAT v0.6: microtiming and groove templates (E6.2, E6.4, E6.5) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build v0.6 of LICHOMAT as specified in `docs/superpowers/specs/2026-11-02-v0.6-microtiming-groove.md` (decisions M1–M28, accepted under the owner's delegation): each step's own offset at one tick (`mic`, −84..+84, stored as the coarse shift plus a fine nibble), seven groove templates per track with an amount (`tpl amt`), recording that keeps the played offset (`rqn`), pattern-file block 2, the emulator's `--ticks` check and the goldens G20–G22, with all 32 goldens of v0.5 unchanged, and the owner's checks U33–U37.

**Architecture:** The timing core gets two optional host callbacks, `fine()` and `tmpl()` (NULL means 0 and `off`), the template table and the offset formula of spec §4.1 in `seqc_generate()`: the step's own position P = clamp(C + F + G, ±7L/8), then swing, delay and humanize as before, so with fine 0 and the templates off every event is v0.5's. `PatternSet` holds the fine parts as nibbles (14,336 B) and a `TrackTemplate` per track; block 2 follows block 1 in `.pat` and `tmp.pat` only when it carries data. The menu reaches the sequencer through direct calls; recording places a note with the new core query `seqc_recordPlace()` against the step's reference time (grid + swing + template + delay).

**Tech Stack:** C11 (firmware: Arm GNU 14.3, `-O3 -ffast-math -mfp16-format=ieee`; host tests: Apple clang 17, UBSan, ASan + UBSan; CI: GCC on Linux, strict C11), CMake 3.31, Ninja, ctest, Python 3 (`render_test.py`, `emu_golden.py`, `emu_onsets.py`, `emu_fuzz.py`), bash.

## Spec deviations

1. **§11 step 9 (the budget line) is done in Task 4** (V6-2). Without it the gate of Tasks 4–8 fails the sum rule.
2. **§7.1 step 1: `x` is not `seqc_positionAt(t)`.** That function returns at least the core's position (`seq_core.c:558–564`), so a note stamped before the last boundary would be placed after it, the opposite of §7.1 step 3 ("x may lie a little before c's boundary"). `seqc_recordPos()` gives the internal timeline at `t`, or the slave interpolation from the last clock without the hold (V6-5).
3. **§6.4: the step-select load is one call in `CortexParser.c`** (`FRONT_SEQ_REQUEST_STEP_PARAMS`), not one per `buttonHandler.c` site (V6-7). Same effect, and the menu's `PAR_ACTIVE_STEP` is covered too.
4. **§10.1: the M13 cases of `pattern_block2` are in `test_sequencer.c`**, under the id `sequencer`. `test_presets.c` has stand-ins for `seq_copyPattern()` and the backup buffer (F12), not the real functions.
5. **§6.1: `Micro`, not `Microtime`**, as the long name in edit mode, and the other long names at most 8 characters (V6-19). The 16-column row has 8 columns for it; a longer name runs into the bottom row (F7).
6. **§6.1 and §12: the knob steps `mic` one tick per move, like the encoder.** The knobs are relative (`adcPots.c:232`, `menu.c` `limitPotValue()`, F6), so "about 1.3 ticks per position" does not apply and §12's knob risk does not arise. No knob code changes.
7. **§8, M25 and U37: the recount.** By §8's own static method the added cost is about 216 cycles per call, 1.45 % of a block in the worst case with the factor 1.5, not 0.56 % (V6-23); the executed path is shorter (§8's 83 cycles), so the truth lies between. D41's bound becomes 89.64 + 1.45 = 91.1 < 95. **U37's limit becomes "at most 1.5 points above 1"** (was 1), so a reading inside the static bound is not a failure.
8. **§10.2: G21 sets its shuffle in its own script, each bar; pattern 2's crossings use microtiming, not swing** (V6-15, F5).
9. **§5.3 step 6: only steps with a fine part are clamped and split again** on loading (V6-6). For every other step the split is the identity, except that a stored shift of 15 would become 7; it stays 15 and plays as 0, as in v0.5.
10. **§7.2: `seq_addNote()` keeps its signature; the time goes through the new `seq_addNoteAt()`** (V6-10), so no existing host test changes.

 * step, -84..+84. The coarse part is StepTiming.shift (units of 12 ticks), the fine part a
 * signed nibble -6..+5 in PatternSet.seq_stepFine, 32 bytes a track: byte i holds step 2i in
 * bits 0-3 and step 2i+1 in bits 4-7. The split is canonical: coarse = floor((T + 6) / 12),
 * the nearest unit with ties upwards, which fw 1.7 and v0.2-v0.5 play; fine = T - 12 coarse.
 * A nibble of -8, -7, +6 or +7 counts as 0. Zero bytes are the default. */
#define STEP_MICRO_MAX		84	// ticks: the shift's reach, 7/8 of a step
#define STEP_SHIFT_UNIT		12	// ticks of a shift unit at x1
#define STEP_FINE_MIN		(-6)
#define STEP_FINE_MAX		5
#define STEP_FINE_BYTES		32	// a track's nibbles: 64 steps / 2

/** the fine part of a stored nibble (the low 4 bits of n): -6..+5, any other value 0 */
static inline int8_t stepFine_decode(uint8_t n)
{
	const int f = (n & 0x08u) ? (int)(n & 0x0Fu) - 16 : (int)(n & 0x0Fu);
	return (int8_t)((f < STEP_FINE_MIN || f > STEP_FINE_MAX) ? 0 : f);

static inline int8_t stepFine_get(const uint8_t *track, uint8_t s)
{
	return stepFine_decode((uint8_t)(track[(s >> 1) & 31u] >> ((s & 1u) * 4u)));
}

/** set step s's fine part (its low 4 bits) in a track's STEP_FINE_BYTES */
static inline void stepFine_set(uint8_t *track, uint8_t s, int8_t fine)

	uint8_t *b = &track[(s >> 1) & 31u];
	*b = (uint8_t)((*b & ~(0x0Fu << sh)) | (((unsigned)fine & 0x0Fu) << sh));
